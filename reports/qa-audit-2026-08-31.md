## Prioritized findings

### P1 — High, fixed locally: document-area rollout could break screens or hide legacy notes de frais

- The application now reads and writes `receipts.document_area` in `src/app/(app)/inbox/page.tsx:245-249`, `src/app/(app)/receipts/ReceiptsManager.tsx:111-116`, and `src/app/api/ocr/route.ts:87-98`.
- Resolution: migration `089` adds a dedicated `legacy` classification before enforcing the default and constraint. Both workspaces include legacy rows, while newly uploaded rows remain strictly separated.
- Regression coverage: `src/lib/document-area.test.ts` verifies visibility and separation rules.
- Deployment requirement: commit and apply migration `089` before deploying code that queries `document_area`.

### P1 — High, fixed locally: subscription/account updates were not atomic

- Resolution: migration `090` provides the bulk lifecycle transaction, while migration `091` provides `admin_set_company_access_priced` and `admin_save_company_pricing`. Account state, subscription history, saved pricing, and effective limits now commit or roll back as one logical database transaction.
- Regression coverage: `src/lib/subscription-dates.test.ts` verifies ordinary, month-end, leap-year, and annual renewal dates.
- Deployment requirement: apply migrations `090` and `091` before deploying the updated admin routes.

### P2 — Medium, fixed locally: user suspension/reactivation could produce split Auth and membership state

- Resolution: membership state is now captured and updated before Auth. If Auth fails, each affected membership is restored to its exact previous state and any compensation failure is reported explicitly.
- Residual limitation: Supabase Auth and Postgres cannot share a single transaction; production monitoring should alert on the explicit “restauration ... incomplète” error path.

### P2 — Medium, fixed: E2E release gate was failing on desktop and mobile

- Resolution: the assertion follows the current section heading and the suite now checks `/tableau-de-bord`, `/factures`, `/notes-de-frais`, and `/parametres` for redirect-loop-free anonymous protection.
- Verification: **10/10 E2E checks pass** across desktop and mobile Chromium.

### P2 — Medium: public legal pages still expose unresolved placeholders

- `src/app/cgu/page.tsx:107` has no confirmed post-termination access duration.
- `src/app/cgu/page.tsx:183` has no confirmed jurisdiction.
- `src/app/confidentialite/page.tsx:128-130` has no account/log retention periods.
- `src/app/confidentialite/page.tsx:177` has an unresolved analytics-cookie disclosure.
- Impact: public contractual/privacy text is incomplete and cannot be verified against operations.
- Recommendation: obtain legal/privacy-owner sign-off and block production builds when public legal pages contain `[TODO:`.

### P3 — Low: lint passes with substantial correctness-oriented warning debt

- ESLint reports **111 warnings** and zero errors.
- Breakdown: 33 missing hook dependencies, 22 state updates inside effects, 5 render-purity warnings, 4 components created during render, 2 immutability warnings, 2 memoization warnings, 2 accessibility warnings, and 38 lower-risk unused/image/style warnings.
- The largest concentration is `src/app/(app)/paie/page.tsx` with 19 warnings.
- Impact: stale closures and non-idempotent render behavior can become user-visible state or refresh defects; warning-only enforcement allows new debt into the release.
- Recommendation: promote correctness rules to errors after a focused cleanup, starting with tenant/dossier-scoped screens and money-changing workflows.

### P3 — Low: high-risk server flows still need integration coverage

- Document-area selection and public localized routes now have regression coverage, but the suite still does not execute the new database functions against a disposable Supabase database or inject Auth/membership failures.
- Recommendation: add database-backed integration tests for subscription renewal/restart, bulk lifecycle changes, compensation paths, RLS boundaries, and tenant isolation.

## Limitations

It did not inspect the live Supabase schema/RLS catalog, production migration state, production logs/Sentry, backups/restores, real OAuth providers, email delivery, billing records, or an authenticated production browser session. It is a QA release-readiness review, not a formal security, legal, or compliance attestation.
